# 세종 로컬 해결소(가칭) 시연 사이트

고려대학교 세종캠퍼스 서비스러닝 '소셜벤처링' 4조의 발표 시연용 웹사이트입니다.
기획은 `SPEC.md`, 배경과 수치 출처는 `docs/CONTEXT.md`를 보세요(팀원 이름이 있어서 공개 저장소에는 올리지 않습니다).

## 내 컴퓨터에서 열기

`index.html`을 더블클릭하면 열리지 않습니다(브라우저가 파일 경로에서는 ES 모듈과 JSON 읽기를 막습니다).
이 폴더에서 아래 명령을 실행한 뒤 브라우저로 `http://localhost:8791` 에 들어가세요.

```bash
python -m http.server 8791
```

- 체험: `http://localhost:8791`
- 기관 대시보드: `http://localhost:8791/dashboard.html`
- 분류기 테스트: `http://localhost:8791/tests/classifier.test.html`

서버(구글 시트)를 연결하기 전에는 **오프라인 시연 모드**로 동작합니다. 같은 브라우저에서 체험을 제출하면 대시보드 '방금 들어온 고민'에 '이 기기'로 바로 더해집니다.

## 구글 시트 + Apps Script 연결하기

총 7단계, 20분 정도 걸립니다. 학교 계정은 외부 접속이 막힐 수 있으니 **개인 구글 계정**으로 하세요.
구글 화면이 영어로 나오면 괄호 안의 영어 이름을 찾으면 됩니다.

### 1. 구글 시트 만들기

1. 개인 계정으로 로그인한 상태에서 브라우저 주소창에 `sheets.new` 를 입력하고 엔터를 누릅니다.
2. 왼쪽 위 '제목 없는 스프레드시트'를 눌러 이름을 `세종 로컬 해결소 접수` 로 바꿉니다.
3. 시트 안에는 아무것도 적지 않아도 됩니다. 4단계에서 스크립트가 `접수` 탭과 머리글을 만듭니다.

### 2. Apps Script에 코드 붙여 넣기

1. 시트 위쪽 메뉴에서 **확장 프로그램(Extensions) → Apps Script** 를 누릅니다. 새 탭에 편집기가 열립니다.
2. 왼쪽 위 '제목 없는 프로젝트'를 눌러 이름을 `세종 로컬 해결소` 로 바꿉니다.
3. 가운데 `Code.gs` 에 있는 기본 내용(`function myFunction() {...}`)을 모두 지웁니다.
4. 이 저장소의 `apps-script/Code.gs` 파일을 메모장 등으로 열어 **전체를 복사**해 붙여 넣습니다.
5. `Ctrl + S` 로 저장합니다.

### 3. 관리자 초기화 키 넣기 (코드에는 넣지 않습니다)

관리자 키는 발표 전에 시연 데이터를 비울 때만 쓰는 비밀번호입니다. 코드와 저장소에는 절대 적지 않고, 스크립트 속성에만 저장합니다.

1. 키로 쓸 값을 만듭니다. 아래 명령을 실행하면 추측하기 어려운 문자열이 한 줄 나옵니다(직접 지어도 되지만 영문·숫자 16자 이상으로 하세요).

   ```bash
   python -c "import secrets; print(secrets.token_urlsafe(16))"
   ```

2. Apps Script 편집기 왼쪽의 **톱니바퀴(프로젝트 설정, Project Settings)** 를 누릅니다.
3. 맨 아래 **스크립트 속성(Script Properties) → 스크립트 속성 추가(Add script property)** 를 누릅니다.
4. 속성(Property)에 `ADMIN_KEY`, 값(Value)에 1번에서 만든 문자열을 넣고 **스크립트 속성 저장(Save script properties)** 을 누릅니다.
5. 키는 발표자만 알고 있으면 됩니다. 팀 단톡방이나 저장소에 올리지 마세요.

### 4. 권한 승인하고 시트 탭 만들기

1. 왼쪽 **< > 편집기(Editor)** 로 돌아갑니다.
2. 위쪽 도구 막대의 함수 선택 칸에서 `setup` 을 고르고 **실행(Run)** 을 누릅니다.
3. '승인 필요(Authorization required)' 창이 뜨면 **권한 검토(Review permissions)** → 내 계정을 고릅니다.
4. 'Google에서 확인하지 않은 앱(Google hasn't verified this app)' 경고가 나옵니다. 내가 만든 스크립트라서 나오는 정상 화면입니다. **고급(Advanced) → 세종 로컬 해결소(으)로 이동(안전하지 않음)** → **허용(Allow)** 을 누릅니다.
5. 아래 실행 로그에 '실행 완료(Execution completed)'가 보이면 시트 탭으로 돌아가 `접수` 탭과 머리글 한 줄이 생겼는지 확인합니다.

### 5. 웹앱으로 배포하기

1. 편집기 오른쪽 위 **배포(Deploy) → 새 배포(New deployment)** 를 누릅니다.
2. '유형 선택' 옆 **톱니바퀴 → 웹 앱(Web app)** 을 고릅니다.
3. 설명에 `v1` 을 적습니다.
4. **다음 사용자 인증 정보로 실행(Execute as): 나(Me)** 로 둡니다.
5. **액세스 권한이 있는 사용자(Who has access): 모든 사용자(Anyone)** 로 바꿉니다. 이걸 바꾸지 않으면 청중 휴대폰에서 제출이 안 됩니다.
6. **배포(Deploy)** 를 누르고, 다시 권한을 물으면 4단계처럼 허용합니다.
7. **웹 앱 URL** 을 복사합니다. `https://script.google.com/macros/s/` 로 시작하고 `/exec` 로 끝나는 긴 주소입니다.
8. 확인: 새 탭 주소창에 복사한 주소 뒤에 `?action=summary` 를 붙여 엽니다. `{"ok":true,"summary":{"total":0,...` 로 시작하는 글자가 보이면 성공입니다.

### 6. 웹앱 주소를 api.js에 넣기

1. 이 저장소의 `js/api.js` 를 엽니다.
2. 위쪽의 아래 한 줄을 찾습니다.

   ```js
   export const API_URL = '';
   ```

3. 따옴표 두 개 **사이에** 5단계에서 복사한 주소를 붙여 넣고 저장합니다. 따옴표는 지우지 마세요.

   ```js
   export const API_URL = 'https://script.google.com/macros/s/AKfy...긴 글자.../exec';
   ```

이 주소는 저장소에 공개되어도 괜찮습니다. 주소를 아는 사람은 누구나 접수를 보낼 수 있지만, 서버는 정해진 선택지만 받고, 체험 화면은 기기당 3회로 막혀 있고, 관리자 키 없이는 지울 수 없습니다. 장난 접수가 쌓이면 발표 직전에 비우면 됩니다.

### 7. 연결 확인하기

1. 로컬 서버를 켜고(`python -m http.server 8791`) 두 탭을 엽니다.
   - 탭 1: `http://localhost:8791/dashboard.html`
   - 탭 2: `http://localhost:8791`
2. 대시보드 오른쪽 위 배지가 **실시간**(초록 점) 인지 봅니다.
3. 탭 2에서 체험을 끝까지 하고 결과 화면의 **이 고민 제출하기** 를 누릅니다. 청록 완료 화면에 **발표 화면을 봐주세요!** 가 나오면 전송 성공입니다. **이 기기에 저장했어요** 가 나오면 전송 실패입니다(아래 '문제가 생기면').
4. 대시보드의 '접수된 고민' 숫자가 오르고, 해당 유형 막대가 노랗게 반짝이는지 봅니다. 구글 시트 `접수` 탭에도 한 줄이 생깁니다.
5. 휴대폰 테스트는 아래 'GitHub Pages로 배포하기'를 마친 뒤에 합니다. 휴대폰은 내 컴퓨터의 `localhost` 에 들어올 수 없습니다.

## GitHub Pages로 배포하기

저장소 이름은 `sejong-local-solver`, 배포 주소는 **https://lucky-lake.github.io/sejong-local-solver/** 입니다.
`assets/qr.png` 는 이 주소로 미리 만들어 두었습니다. 저장소 이름을 바꾸면 QR도 다시 만들어야 합니다.

### 0. 올리기 전에 알아 둘 것

- 공개 저장소라서 올린 파일(SPEC.md, CLAUDE.md 포함)은 누구나 볼 수 있습니다. 팀원 이름이 든 `refs/`(개요서 PDF)와 `docs/`(CONTEXT.md)는 `.gitignore` 로 빠집니다. 두 폴더는 이 컴퓨터에만 남으니 팀원에게는 따로 보내 주세요.
- Apps Script 웹앱 주소를 이미 `js/api.js` 에 넣었다면 그대로 올라가도 괜찮습니다(위 6단계 설명 참고). 관리자 키는 어디에도 적혀 있지 않습니다.
- `.nojekyll` 파일은 GitHub가 사이트 파일을 바꾸지 않고 그대로 내보내게 하는 빈 파일입니다. 지우지 마세요.

### 1. 이 폴더에서 터미널 열기

이 폴더(sejong-local-solver)에서 PowerShell이나 Windows 터미널을 엽니다. 아래 명령은 모두 이 폴더 안에서 한 줄씩 실행합니다.

### 2. 내 컴퓨터에 저장소 만들기 (처음 한 번)

```bash
git init -b main
```

커밋 기록에는 이메일이 함께 남고, 공개 저장소에서는 누구나 볼 수 있습니다. 개인 메일 대신 GitHub가 주는 개인정보 보호용 주소를 이 저장소에서만 쓰도록 설정합니다. 주소는 GitHub **Settings → Emails** 의 'Keep my email addresses private' 아래에 나오는 `숫자+lucky-lake@users.noreply.github.com` 입니다.

```bash
git config user.email "숫자+lucky-lake@users.noreply.github.com"
```

```bash
git add .
```

```bash
git status
```

목록에 `refs/` 와 `docs/` 가 **없고** `assets/qr.png`, `.nojekyll`, `.gitignore` 가 있으면 됩니다.

```bash
git commit -m "시연 사이트 첫 배포"
```

### 3. GitHub에 올리기

```bash
gh repo create sejong-local-solver --public --source . --remote origin --push
```

GitHub에 공개 저장소를 만들고 방금 커밋을 올립니다. `gh` 를 찾을 수 없다고 나오면 PowerShell에서 `& "C:\Program Files\GitHub CLI\gh.exe"` 를 `gh` 자리에 넣어 실행합니다.

### 4. GitHub Pages 켜기

1. 브라우저에서 `https://github.com/lucky-lake/sejong-local-solver` 를 엽니다.
2. 위쪽 **Settings → 왼쪽 메뉴 Pages** 를 누릅니다.
3. **Build and deployment → Source** 를 `Deploy from a branch` 로 둡니다.
4. **Branch** 를 `main`, 폴더를 `/ (root)` 로 고르고 **Save** 를 누릅니다.

### 5. 배포 확인

1. 저장소 위쪽 **Actions** 탭에서 `pages build and deployment` 옆에 초록 체크가 뜰 때까지 1~2분 기다립니다.
2. 휴대폰 데이터(와이파이 끄고)로 `https://lucky-lake.github.io/sejong-local-solver/` 를 열어 첫 화면이 뜨는지 봅니다.
3. 노트북에서 `https://lucky-lake.github.io/sejong-local-solver/dashboard.html` 을 열고, 오른쪽 QR을 휴대폰 카메라로 찍어 사이트가 열리는지 봅니다. **QR 확인은 이 단계가 최종입니다.**
4. 휴대폰에서 체험을 끝까지 하고, 대시보드 숫자가 오르는지 봅니다(Apps Script 연결을 마친 경우).

### 6. 고친 뒤 다시 올리기

```bash

```

```bash

```

```bash

```

1~2분 뒤 반영됩니다. 휴대폰에서 예전 화면이 보이면 새로고침하세요(GitHub가 최대 10분까지 예전 파일을 보여 줄 수 있습니다).

## 발표 때 쓰는 기능

### 대시보드 키보드 조작

| 키 | 하는 일 |
|---|---|
| R | 바로 새로고침 (평소에는 3초마다 자동) |
| S | 예시 데이터 25건 켜기/끄기 (오른쪽 위 배지가 '예시 데이터 포함' ↔ '실제 접수만'으로 바뀜) |
| F | 전체화면 |

한글 자판 상태여도 동작합니다.

### 글꼴

제목 글꼴(Jua)과 본문 글꼴(Noto Sans KR)은 구글 글꼴에서 받아 옵니다. 화면은 글꼴을 기다리지 않고 먼저 뜨고, 인터넷이 없으면 기기 기본 글꼴로 보입니다. 발표장에서 제목이 둥근 글씨(Jua)로 보이는지 미리 확인하세요.

### 시연 데이터 비우기 (발표 직전)

1. 프로젝터를 연결하기 **전에** 주소창에 `.../dashboard.html?admin=관리자키` 를 입력해 엽니다.
2. 열리자마자 주소창에서 키 부분은 자동으로 지워집니다.
3. 오른쪽 아래 **시연 데이터 비우기** 를 누르고 확인을 누릅니다. 시트의 접수 기록만 지워지고 예시 데이터 25건은 남습니다.

### 알아 둘 것

- 첫 요청은 구글 서버가 깨어나느라 몇 초 걸릴 수 있습니다. 발표 1~2분 전에 대시보드를 미리 열어 두세요.
- 대시보드는 3초마다 집계를 받아 옵니다. 구글 응답 시간에 따라 반영까지 3~5초쯤 걸릴 수 있습니다.
- 자유 입력 원문은 시트에만 저장되고 대시보드로 보내지 않습니다. 연락처처럼 보이는 숫자와 욕설은 저장 전에 가립니다.
- 한 기기는 3번까지만 발표 화면에 올라갑니다. 리허설 중 내 휴대폰이 막히면 브라우저 설정에서 이 사이트 데이터를 지우거나 시크릿 탭을 쓰세요.
- 연결이 끊기면 체험은 그대로 진행되고 접수는 기기에 저장됩니다. 연결이 돌아오면 자동으로 다시 보냅니다(서버가 같은 접수를 두 번 세지 않습니다).
- 대시보드는 연결이 끊기면 마지막 집계를 유지하고 '연결 끊김' 배지를 띄웁니다. 처음부터 연결이 안 되면 예시 데이터로 돌아갑니다.

### 코드를 고친 뒤 다시 배포하기

`apps-script/Code.gs` 를 고쳤다면 편집기에 다시 붙여 넣고 저장한 뒤, **배포 → 배포 관리(Manage deployments) → 연필(수정) → 버전: 새 버전(New version) → 배포** 를 누릅니다. 이렇게 하면 웹앱 주소가 바뀌지 않습니다. '새 배포'를 다시 만들면 주소가 바뀌어 6단계를 다시 해야 합니다.

### 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 대시보드 배지가 '서버 연결 안 됨' | 5단계 7번 주소가 `/exec` 로 끝나는지, 액세스 권한이 '모든 사용자'인지, 코드 수정 후 새 버전으로 배포했는지 |
| 완료 화면에 '이 기기에 저장했어요' | 위와 같음. 접수는 기기에 남아 있다가 연결되면 다시 보냅니다 |
| '관리자 키가 맞지 않아요' | 주소의 `admin=` 뒤 값이 스크립트 속성 `ADMIN_KEY` 값과 같은지 |
| '스크립트 속성에 ADMIN_KEY가 없어요' | 3단계를 다시 하고, 속성 이름이 대문자 `ADMIN_KEY` 인지 |
| 학교 계정에서 '권한 없음' | 개인 계정으로 1단계부터 다시 |

### 발표가 끝나면

- 구글 시트의 `접수` 탭 기록을 지웁니다(SPEC 8장).
- 웹앱을 멈추려면 **배포 → 배포 관리 → 보관(Archive)** 을 누릅니다.
